# Design: поддержка bd >= 1.0.0 и миграция 0.47 → 1.0.5

- **Задача:** claude-tools-elf.20
- **Дата:** 2026-06-24
- **Связанные:** claude-tools-elf.21 (использование новых фич bd 1.0 — отдельно, зависит от этой), инцидент claude-tools-elf.19 (PATH-shadowing старым bd)

> **Ревизия (2026-06-24, по ходу реализации): scope сокращён.** При установке реального bd 1.0.5 обнаружено, что 1.0.x **полностью удалил `bd sync` и подкоманду `bd daemon`** — синхронизация стала Dolt-native (`bd export` / `bd vc` / `bd federation`, Dolt auto-push). Это глубже, чем предполагал раздел 4 (ожидался лишь opt-in JSONL). Поскольку flow завязан на `bd sync`/демон и пока НЕ работает на 1.0.x, а version-guard, требующий `>= 1.0.0`, сломал бы текущую работу на 0.47.x, принято решение **отложить** enforcement guard и катовер окружения.
>
> **elf.20 теперь поставляет (не ломая 0.47.x):** рендер типа `decision`; фикстуры реального bd 1.0.5 + тесты совместимости парсеров; хелпер `flow-require-bd` (готов, протестирован, НЕ подключён к скиллам); README-заметку о совместимости версий bd. Шаги «version-guard в скиллах» (раздел 2/Component 2) и «катовер/удаление standalone» откатаны/исключены из elf.20.
>
> **Вынесено в claude-tools-akt:** редизайн sync/persistence flow под Dolt-native bd 1.0.x, подключение guard и собственно катовер на 1.0.5. DoD ниже относится к ФИНАЛЬНОМУ состоянию миграции и закрывается в akt, а не в elf.20.
>
> *Примечание по реализации:* override-переменная bd в тексте ниже названа `BD` — фактически реализована как **`BD_BIN`** (консистентно с существующими хелперами `flow-branch-for`/`flow-current-task`, тестами и README).

## Контекст и цель

flow вызывает `bd` (beads) исключительно через CLI и парсит его `--json`-вывод. Сейчас нигде нет проверки версии bd: при старом или несовместимом bd flow падает непонятными ошибками (`unknown flag`, Python traceback) — именно это произошло в elf.19, где Homebrew bd 0.44.0 затенял рабочий бинарь.

**Политика:** flow официально поддерживает только `bd >= 1.0.0`. Все версии `< 1.0.0` считаем alpha и не поддерживаем. При несовместимой версии flow должен **явно** требовать обновления с понятным сообщением, а не падать.

**Версии (на 2026-06-24):** стабильная bd — 1.0.5 (2026-05-28), мажор 1.0.0 (2026-04-02), в разработке 1.1.0-rc.1. На машине разработчика установлены только 0.47.1 (`~/.local/bin`, активный, обслуживает daemon) и 0.44.0 (Homebrew) — ни одного 1.0.x.

**Цель задачи:** совместимость flow с bd 1.0.0+ (минимум проверено на 1.0.5) и **документация** сценария миграции пользователя с 0.47.x на 1.0.5. Использование новых возможностей bd 1.0 вынесено в elf.21.

## Ключевые решения

1. **Backward-compat с 0.47 не поддерживаем.** Version-guard падает быстро *до* любого парсинга, поэтому парсеры ориентируются только на схему 1.0.x. Двойную совместимость схем не тащим — это упрощает код.
2. **bd 1.0.5 для тестов ставим изолированно.** Отдельный бинарь (например `~/.local/bin/bd-1.0.5` или бинарь в worktree), на который flow/тесты указывают через переменную окружения `BD` / PATH только в рамках сессии. Рабочий 0.47.1 и daemon не трогаем, чтобы не сломать другие in-progress задачи, пока flow ещё не совместим.
3. **Миграция — только документация.** flow не лезет в `.beads/*.db`; саму миграцию данных делает bd. flow описывает корректный путь и каноном считает `.beads/issues.jsonl`.
4. **Version-guard — единый шаред-хелпер** `bin/flow-require-bd`, который вызывают первой командой все скиллы, обращающиеся к bd.

## Компоненты

### 1. `bin/flow-require-bd` (новый)

Standalone Python-хелпер в стиле остальных `bin/`-скриптов: `#!/usr/bin/env python3`, `from __future__ import annotations` (py3.9-совместимость), `subprocess.run(..., check=False)`, `main() -> int`, поддержка env-override.

Поведение:
- Резолвит бинарь bd через `shutil.which`, уважая опциональный override `BD` (имя/путь бинаря). Это и рычаг против PATH-shadowing (elf.19), и способ указать на изолированный 1.0.5 в тестах.
- Запускает `bd version`, парсит ведущий semver (`bd version 1.0.5 (...)` → `(1, 0, 5)`), сравнивает с единственной константой `MIN_BD = (1, 0, 0)`.
- `>= MIN_BD` → exit 0, тихо (ничего не печатает).
- `< MIN_BD` → печать в **stderr**: резолвнутый путь бинаря, найденная версия, требуемая версия, одна строка «обновите bd / см. README#требования-к-bd-и-миграция». Exit ≠ 0.
- bd не найден / `bd version` не парсится → отдельное понятное сообщение, exit ≠ 0.
- Печать резолвнутого пути делает PATH-shadowing мгновенно видимым.
- `MIN_BD` здесь — единственный источник истины; README документирует то же число.

### 2. Интеграция guard в скиллы

В начало каждого bd-скилла добавляется «Шаг 0: require bd», который запускает `flow-require-bd` **первой** командой. При exit ≠ 0 скилл останавливается и показывает сообщение — ни одного вызова `bd` не делается.

Покрытие — **все скиллы, вызывающие bd**: `start`, `continue`, `decompose`, `done`, `after-design`, `after-plan`, `review-comments`, `sonar-sync`. Стоимость — одна строка на скилл; гарантирует, что ни одна точка входа (включая прямой вызов `after-*`) не упадёт непонятно.

### 3. Совместимость схемы JSON

На изолированном bd 1.0.5 снять реальный вывод `bd graph --all --json`, `bd show <id> --json`, `bd list --json` и сверить с полями, которые читают скрипты:

- **graph** → `Issues[].{id, title, status, priority, issue_type, labels, assignee, description}`, `Dependencies[].{type, issue_id, depends_on_id}`
- **show** → list-или-object с `{id, title, issue_type, status, priority, labels, description, dependencies[].{dependency_type, id, title, status}}`
- **list** → list, либо object с ключом `issues`

Починить расхождения (переименования полей, сдвиг структуры из-за перехода на Dolt и нормализации типов/статусов) в `flow-task-tree`, `flow-find-leaf`, `flow-task-card`, `flow-branch-for`, `flow-current-task`.

> **Уточнение (2026-06-24, по факту bd 1.0.5):** реальный вывод снят и зафиксирован в `plugins/flow/bin/tests/fixtures/{graph,show,list}-1.0.5.json`. Схема **совместима** с текущими парсерами — правки кода парсеров (кроме таблицы типов выше) не требуются:
> - `graph --all --json` — список связных компонент `[{Root, Issues[], Dependencies[]|null, IssueMap, VarDefs, Phase, Pour}]`; flow итерирует компоненты и делает `Dependencies or []` (null обрабатывается).
> - `Issues[]` несут `id, title, status, priority, issue_type, assignee, labels, description` (пустые поля опускаются — парсеры используют `.get(k, default)`).
> - `Dependencies[]`: `type` (`parent-child`/`blocks`), `issue_id`, `depends_on_id` — без изменений.
> - `show --json` — список с `description, labels, dependencies[].dependency_type, parent` — совпадает с тем, что читают `flow-task-card`/`flow-branch-for`.
> Итог: раздел 3 сводится к добавлению типа `decision` и к закреплению совместимости тестами на фикстурах.

**Новый тип issue `decision`** (первого класса, добавлен в bd 1.0.x; алиасы `dec`/`adr` — ADR) добавить в `TYPE_LETTERS` + `TASK_TYPE_EMOJI` (`flow-task-tree`), `TYPE_LETTERS` (`flow-find-leaf`) и `TYPE_WORDS` (`flow-task-card`). Сейчас рендерится как дефолтное `T` / `❔`. Обозначение: `decision → D / ⚖️ / "Decision"`.

> **Уточнение (2026-06-24, по факту bd 1.0.5):** встроенные типы bd 1.0.5 — `bug|feature|task|epic|chore|decision`. Изначально предполагавшихся `spike/story/milestone` среди встроенных **нет** (они существуют только как кастомные типы через `types.custom`), поэтому из scope исключены. Реальный новый встроенный тип — `decision`.

### 4. `bd sync` / daemon при opt-in JSONL (1.0.5)

Breaking change 1.0.5: авто-экспорт и авто-staging JSONL стали **opt-in** (раньше по умолчанию). Шаги `bd sync` в flow предполагают, что `.beads/issues.jsonl` пишется и коммитится. Проверить на 1.0.5 и поправить: либо включить opt-in, либо добавить явный шаг экспорта. Заодно обновить рекомендации по трению daemon ↔ git (см. reference_beads_daemon_git_friction): worktrees делят одну БД, daemon может коммитить не в ту ветку — фиксируем актуальную рекомендацию (`BEADS_NO_DAEMON=1` и т.п.).

### 5. Документация миграции (README)

Новый раздел в `plugins/flow/README.md` (например, «Требования к bd и миграция»):
- Минимально требуемая версия: `bd >= 1.0.0` (рекомендуется 1.0.5).
- Путь обновления 0.47.x → 1.0.5.
- Что происходит с `.beads`: в 0.58 SQLite полностью удалён, единственный бэкенд — встроенный Dolt (в 1.0.0 по умолчанию на macOS). Каноном flow считает `.beads/issues.jsonl`, поэтому корректный путь — пересборка БД из JSONL средствами bd (а не ручное вмешательство flow в `.db`).
- Заметка про opt-in JSONL в 1.0.5.
- Caveat про PATH-shadowing (elf.19) и `BD`-override / `which -a bd`.

Сообщение об ошибке version-guard ссылается на этот раздел.

## Definition of Done

- flow проверен и работает на bd >= 1.0.0 (минимум на 1.0.5).
- В начале всех bd-скиллов есть version-guard с понятным сообщением при bd < 1.0.0.
- README плагина указывает минимально требуемую версию bd.
- тип `decision` рендерится корректно в дереве/списке/карточке.
- Описан корректный путь миграции пользователя с 0.47.x на 1.0.5 (что делать с существующей БД/JSONL).

## Вне scope (→ claude-tools-elf.21)

Использование новых возможностей bd 1.0: `bd batch` / `bd create --graph`, `bd ready --json`, `bd close --claim-next` / `--reason-file`, multi-status `bd list --status=a,b`.
